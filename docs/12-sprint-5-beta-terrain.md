# Sprint 5 - Beta Terrain

## Objectif SMART

D'ici la fin du sprint, 10 commercants testeurs doivent pouvoir realiser au moins 50 encaissements de test ou reels, avec moins de 2 blocages majeurs par commercant.

Mesures d'acceptation:
- environnement beta/staging stable;
- guide testeur disponible;
- collecte des retours structuree;
- KPIs minimum releves;
- bugs bloquants priorises dans un backlog.

## Sprint Goal

Passer d'un produit valide techniquement a un produit confronte au terrain.

## Backlog priorise

### P0 - Environnement beta stable

User story:
- En tant que testeur, je peux utiliser une URL/API beta sans casser la production.

Criteres d'acceptation:
- variables beta separees;
- base de test identifiable;
- OTP sandbox ou procedure OTP documentee;
- donnees de demo/test reproductibles;
- healthcheck API surveillable.

Statut:
- a faire.

### P0 - Guide testeur

User story:
- En tant que commercant testeur, je sais quoi essayer et comment signaler un probleme.

Criteres d'acceptation:
- parcours encaissement cash;
- parcours Wave manuel;
- consultation historique;
- partage recu;
- formulaire ou format de retour bug;
- criteres de blocage clairs.

Statut:
- a faire.

### P0 - KPIs minimum

User story:
- En tant que product owner, je peux mesurer si le MVP tient sa promesse.

Criteres d'acceptation:
- transactions initiees;
- transactions confirmees;
- transactions annulees;
- recus partages;
- temps approximatif d'encaissement si mesurable;
- erreurs API critiques.

Statut:
- a faire.

### P1 - Backlog retours terrain

User story:
- En tant qu'equipe, je peux transformer les retours beta en decisions produit.

Criteres d'acceptation:
- chaque retour a source, impact, frequence et statut;
- bugs bloquants separes des idees;
- demandes de fonctionnalites classees par segment;
- decision explicite: faire, attendre, refuser.

Statut:
- a faire.

### P1 - Support minimum

User story:
- En tant que support, je peux aider un testeur qui a une transaction ambigue.

Criteres d'acceptation:
- recherche par reference transaction;
- recherche par telephone marchand;
- procedure de lecture logs;
- procedure de rollback/annulation documentee.

Statut:
- a faire.

## Hors sprint

- paiement automatique provider;
- inventaire complet;
- multi-boutique;
- abonnement/paiement SaaS.

## Plan de test sprint

1. Deployer ou configurer l'environnement beta.
2. Creer les comptes testeurs.
3. Faire un dry-run interne complet.
4. Donner le guide aux testeurs.
5. Collecter les retours tous les jours.
6. Trier bugs bloquants, irritants et idees.
7. Produire une synthese de fin beta.
